## 接口与身份

| 方法 / 路径 | 输入 | 成功 data |
| --- | --- | --- |
| PUT /api/items/{id}/favorite | 无 body 或空对象 `{}`；无查询参数 | `{itemId,favorited:true}` |
| DELETE /api/items/{id}/favorite | 无 body 或空对象 `{}`；无查询参数 | `{itemId,favorited:false}` |
| GET /api/favorites | `page=1&size=12` | `{records,total,page,size}` |

均使用现有 Bearer 会话，user_id 来自服务端。管理员也只管理自己的收藏，不提供访问他人收藏、收藏用户列表或公开收藏人数接口。写入不接受 userId、ownerId、role、itemId 等 body 字段或查询参数；路径 id 为正整数。列表只接受 page/size 各一次，page≥1、size1–100；不允许通过额外用户参数切换身份。

## 可见性、占位及计数

| 物品当前状态 | 添加 | 已收藏列表 | 取消 |
| --- | --- | --- | --- |
| AVAILABLE / RESERVED / EXCHANGED | 200，可重复 | itemVisible=true，item 为当前公开 ItemView | 200 |
| DRAFT / PENDING_REVIEW / HIDDEN | 404，包括此前已收藏及自己的非公开物品 | itemVisible=false，item=null | 200 |
| 不存在的正整数ID | 404 | 正常外键不允许悬空关系；读取仍保留不可见占位语义 | 200，不泄露存在性 |

公开可见性复用 ItemService，与公开列表/详情保持一致。itemVisible 指公开可读，不代表 AVAILABLE、无占用或能交换；收藏不会占用物品。可收藏自己的公开物品。账号停用不自动删除既有公开物品，收藏中的物品显示沿用现有公开详情规则；被停用的收藏者自身会话则不能访问接口。

收藏关系持久化保存 itemId 和收藏时间，不复制标题/图片等物品内容。下架后占位记录只能返回 `{itemId,favoritedAt,itemVisible:false,item:null}`；即使当前会话拥有该物品，也不能借收藏列表读取非公开详情。D 显示“物品暂不可见”、保留取消按钮，不显示旧缓存中的标题、缩略图、owner或状态，不再打开公开详情。

`total` 计算本人全部收藏关系，包含不可见占位。服务端先对关系分页，再在同一只读快照批量取公开物品，因此不会因隐藏物品丢掉页面记录或产生错误 total。按收藏时间降序、关系ID降序；同秒收藏仍稳定排序。无收藏返回 records=[]、total=0；超出最后一页返回 records=[]，但total保留真实关系总数。

物品内容变更会在收藏列表显示当前公开内容。未来目标再次公开可见时占位自然恢复，不重新添加关系；这不代表本批实现了上架/审核能力。取消后再添加则创建新的收藏记录和排序位置。

## 幂等与错误恢复

重复添加不产生新行、不刷新收藏时间和排序位置；并发添加所有成功响应均为 favorited=true，数据库仅保留一行。每次添加仍检查可见性：目标后来变为不可见时返回404，并保留已有收藏供列表占位及取消。

重复取消、尚未收藏、目标不可见或不存在时均为200及 favorited=false，只删除当前用户的关系。不存在的目标不会留下墓碑。该物品其他用户的收藏、物品正文、上传、履历、需求与交换完全不变。

| 结果 | D-02 行为 |
| --- | --- |
| 200 | 根据返回 favorited 更新本次视图；刷新收藏列表和分页总数 |
| 400 | 显示 msg，检查ID/分页及误传的JSON展示字段或身份参数 |
| 401 | 沿用现有会话失效处理；切换账号时清除收藏缓存和未完成请求的展示上下文 |
| 添加404 | 提示“物品不存在或暂不可见”，刷新列表/详情；不能把“添加失败”当成已有收藏已删除 |
| 网络失败/响应丢失 | 显示待确认，回读本人列表；不要伪造成功或用本地数组作为最终数据 |

响应结构继续为 HTTP状态对应 `{code,msg,data}`。一个接口成功后，另一个会话可能继续添加/取消；结果不承诺永久不变。同目标写入按数据库获得锁的顺序执行。D 应限制同一物品的并发交互，异步结果绑定发起账号，重新登录后从服务端重新读取。

当前 UniApp `src/common/http.js` 只有 get/post/patch，D 接入时在同一 request 封装补充 PUT/DELETE 代理；不要引入第二套HTTP客户端。保留现有401处理、超时、静默错误及取消能力。本批只提供接入契约，没有实现这些代理或用户页面。

## 虚构分页示例

可见记录的 item 为与 `GET /api/items/{id}` 完全相同的公开 ItemView；以下示例展示只有不可见占位的完整分页，避免伪造真实上传或身份信息：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "records": [
      {
        "itemId": 4101,
        "favoritedAt": "2026-09-08T02:00:00Z",
        "itemVisible": false,
        "item": null
      }
    ],
    "total": 1,
    "page": 1,
    "size": 12
  }
}
```

取消该关系使用 `DELETE /api/items/4101/favorite`，不发送用户ID；成功 data 为 `{"itemId":4101,"favorited":false}`。随后列表 total=0；再次取消返回相同 data。

## 存储与验证

V5 新增 cl_favorite：id、user_id、item_id、created_at，unique(user_id,item_id)，用户和物品外键均 RESTRICT，按用户/时间/ID建索引。V1–V4和旧数据不改；取消只删除私人收藏关系，外键不会级联删除物品或用户。独立需求/推荐/交换表及算法未变。

添加与取消在 READ_COMMITTED 事务先锁 cl_item，再查写关系；添加在获得锁后复用当前公开详情校验，防止等锁期间下架仍被添加。该策略会串行化同一物品的收藏写入，不对所有物品加全局锁。数据库唯一约束防重复，列表在 REPEATABLE_READ 只读快照内统计和批量回读，没有写入。
