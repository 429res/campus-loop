# A-05 认证与上传限流

状态：本切片实现单实例后端的认证与上传应用层限流、代理来源边界、429 契约和自动化验证；不代表整个 A-05 完成。多实例共享计数、网关层流量防护及目标平台部署仍待部署拓扑确定。

## 已确认范围与待决策

仓库当前只有一个 Spring Boot 进程、本机 MySQL 和反向代理说明，没有负载均衡、多实例编排、共享 Redis 或已确认的生产代理网段。因此本切片采用进程内并发安全固定窗口，不增加中间件；结果只证明单实例一致计数。

部署前最小决策是：确定后端是否会有两个或更多实例，以及列出能直接连接后端的反向代理 IP/CIDR。多实例必须先选定共享原子计数服务或在统一网关限流，不能把各 JVM 的计数相加后声称全局一致。未确认代理时保持 `CAMPUS_RATE_LIMIT_TRUSTED_PROXIES` 为空，并让后端按直连地址计数。

## 接口、主体与默认值

| 接口 | 计数主体 | 默认窗口 |
| --- | --- | --- |
| `POST /api/auth/login` | 经可信边界解析的来源地址 | 10 次 / 1 分钟 |
| `POST /api/auth/register` | 经可信边界解析的来源地址 | 5 次 / 10 分钟 |
| `POST /api/auth/password` | 已认证数据库用户 ID | 5 次 / 10 分钟 |
| `POST /api/uploads`、`POST /api/uploads/evidence` | 已认证数据库用户 ID，共享上传额度 | 20 次 / 1 分钟 |

成功、认证失败和格式错误请求都消耗额度，避免因处理结果不同泄露账号是否存在。登录仍统一返回“账号或密码不正确”；超限也只返回统一错误。密码和上传按用户 ID 计数，改变地址或伪造转发头不能绕过。窗口结束自动恢复，没有永久锁定、账号状态写入或会话撤销。普通读取、资料修改和登出不在本批限流。

429 响应保持统一结构：

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 37
X-RateLimit-Reset: 2026-09-08T12:01:00Z
Content-Type: application/json

{"code":429,"msg":"请求过于频繁，请稍后重试","data":null}
```

`Retry-After` 是至少等待的整数秒（向上取整），`X-RateLimit-Reset` 是该固定窗口的 UTC ISO-8601 结束时刻；跨域配置会显式暴露这两个响应头。C/D 应优先使用 `Retry-After` 展示倒计时并暂时禁用对应提交；倒计时结束允许人工重试，不自动清除有效登录。上传页面应保留本地文件选择，注册/登录/改密表单应保留非敏感输入；不要显示“账号被锁定”。

## 配置与代理信任

根启动命令继续由 `scripts/run.mjs` 读取 `.env` 并传给 Spring Boot。可配置项见 `.env.example`：总开关、最多主体数，以及每组的次数和 Spring `Duration` 窗口（如 `30s`、`5m`）。次数必须大于零、窗口至少一秒，非法值使应用启动失败。进程内主体表默认最多 10000 项；达到上限时过期项先淘汰，仍满则该接口的新主体进入共享溢出桶，以有界内存和保守拒绝优先于绕过。

默认完全忽略 `X-Forwarded-For`。只有请求的 TCP 直连地址命中 `CAMPUS_RATE_LIMIT_TRUSTED_PROXIES` 中逗号分隔的 IP/CIDR，后端才从右向左剥离可信代理，取第一个非可信地址。配置代理时必须同时做到：

1. 只填实际反向代理地址或最小网段，不填客户端、校园网或全互联网网段；
2. 防火墙只允许这些代理直连应用端口；
3. 代理用追加真实对端的方式重写转发链，例如 Nginx 的 `$proxy_add_x_forwarded_for`。

在上述配置下，客户端在最左侧注入的伪造地址不会成为计数主体。若代理会覆盖而非追加，也须保证最后一个值来自代理观察到的真实对端。无效或超过 20 跳的转发链保守回退到直连代理地址。

应用层上传限流发生在身份解析后，保护图片解码、重编码、数据库记录和磁盘写入；Servlet 可能已接收 multipart 内容，因此生产代理仍须保留请求体大小、连接速率和总请求速率限制。本实现不能代替边缘抗流量攻击。

## 已验证与限制

自动化使用可控 UTC 时钟验证精确窗口恢复，64 个并发请求只能成功取得配置的 17 个额度；MVC 集成验证正常请求、统一 429/恢复头、未知账号与错误密码一致语义、未信任转发头不可绕过、认证用户跨地址共享改密/上传额度，以及不在范围内的健康读取不受影响。测试上传使用操作系统临时目录并清理。专项隔离 MySQL 可重复运行 `node scripts/mysql-test.mjs --rate-limit`，脚本创建随机口令的一次性 `_test` 库并在结束后停止、删除容器。

本地仅验证单 JVM。未验证多实例、生产代理/防火墙、云网关、真实公网压力、微信开发者工具或真机；这些结果不能由 H5 或单实例测试替代。没有新增数据库迁移、Redis、外部服务或前端页面。
