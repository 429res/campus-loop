# A-01 第一批：本人资料与修改密码

状态：后端、契约与隔离测试已通过 PR #2 合入。这里只记录本人显示名称与修改密码；后续管理员账号启停切片见 [a01-admin-user-status.md](a01-admin-user-status.md)，注册、校园认证、更多个人信息和细粒度权限仍未实现。

## 接口

`PATCH /api/auth/me` 需要 Bearer 会话，请求只允许：

```json
{ "displayName": "新的显示名称" }
```

服务端去除首尾空白，长度须为1–64字符。成功返回 `{id,username,displayName,role}`；`id/username/role/status/passwordHash` 等额外或受保护字段返回400且不写入。未登录或会话无效返回401。

`POST /api/auth/password` 需要 Bearer 会话，请求只允许：

```json
{ "currentPassword": "当前密码", "newPassword": "新密码" }
```

新密码须为12–64字符且UTF-8不超过72字节。旧密码错误、字段校验失败或额外字段返回400且密码、会话均不变化；未登录或会话无效返回401。成功返回HTTP 200和 `data: null`，同一事务更新 BCrypt 哈希并撤销该账号全部会话，包括当前设备和其他设备。

## 给成员 D 的接入说明

- 资料保存成功后，用响应中的完整公开用户结构替换本地用户缓存，不在客户端合并或发送受保护字段。
- 改密成功收到200后立即清除 `campus-loop-token` 与 `campus-loop-user`，跳转登录页并提示使用新密码登录；不要等待下一次请求返回401才清理。
- 改密400表示输入或旧密码问题，不清除现有登录态；展示服务端 `msg` 后允许用户修正。
- 改密成功后，当前令牌、其他设备原令牌及并发旧密码登录产生的令牌均不可继续使用。旧密码登录返回401，新密码登录成功后获得新会话。
- 不根据错误文案判断分支，以HTTP状态和统一 `code` 为准；不要记录请求密码、令牌或完整响应头。
