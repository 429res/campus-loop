# 自动审核与人工接管

待审核物品、物品举报、动态举报由服务端异步队列处理。千问查看受限的文字与关联图片，输出 APPROVE / REJECT / REVIEW、理由和置信度。明确结论且置信度至少 0.90、无待核实问题才执行；缺图、模型故障、证据不足或并发变更转人工。不是必须依赖 AI 才能操作：管理员保留现有审核入口。

自动审核复用现有审核事务、版本检查、占用检查及通知；独立系统身份不可登录或通过账号管理修改，审计显示“千问自动审核”。举报处理沿现有治理状态机执行，物品举报结论不解除交换占用、不自动裁定线下争议。日常审核结果只发站内通知。

新增 V22：受保护的系统审核身份、AI_REVIEW 来源、持久审核任务和结果。每个对象版本/举报批次最多执行一次，调用模型时不持有业务锁；应用结果时重新校验原始内容摘要。服务崩溃后过期任务转人工，不重复自动批准。管理员能查看 AI 结论、理由、模型、置信度和人工接管原因。

配置 `CAMPUS_AI_AUTO_REVIEW_ENABLED`（默认 false），`QWEN_REVIEW_MODEL`（默认 qwen3-vl-plus），继续复用私密百炼密钥。图片通过服务端本地上传文件读取、缩放后送入模型，不允许模型访问任意 URL 或执行工具指令。结构化多模态接口参见[百炼官方文档](https://help.aliyun.com/en/model-studio/qwen-structured-output)。

## 验证记录（2026-09-09）

- 管理端构建、42 项前端测试、用户端 113 项既有测试通过。后端公共模块 78 项测试通过；223 项 API 测试在隔离 MySQL 8.4.11 中全部通过，H2 回归通过（27 项数据库专属测试跳过）。旧版本升级到 V22 的独立迁移检查通过。
- 新增 8 项自动审核集成场景与 2 项结构化判定检查，覆盖自动通过/驳回、低置信度与异常转人工、内容变更、既有审核、交换占用、双 worker 防重、举报/动态治理及系统身份禁止登录。
- 本机真实千问调用：普通教材与带图校园插画自动 APPROVE，违规工具自动 REJECT；缺少归属证据的举报为 REVIEW 并保留人工队列。后台浏览器实际读取自动审核记录、理由与系统审核人，并打开人工接管入口。
- 自动审核未改动邮件白名单；审核结果仅站内通知。本次没有微信界面变更。服务器启用需要已登录的 ECS 维护会话；部署结果以单独的部署记录为准。
