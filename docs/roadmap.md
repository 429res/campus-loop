# 迭代路线与验收

初始迭代只承诺可安装、可运行、可继续开发的三端工程。实际验证结论见 [verification.md](verification.md)，以下已实现项不等于在每个真实平台都验收通过。

## 初始化实现范围

- 单仓三端、各自前端 lockfile、Maven Wrapper、独立 MySQL Compose、环境加载和本地账号初始化。
- Campus Loop 管理布局、用户端发现首页/发布/详情、共用主题变量、控件实验室与覆盖说明。
- JWT 登录、数据库有效会话、退出撤销；用户发布和读取物品，管理员读取记录与统计。
- 无副作用的双方/三方有向循环匹配、流向与理由、虚构演示物品、边界测试。
- Flyway 迁移、虚构数据幂等插入、隔离后端测试、三种前端构建与 GitHub Actions。
- 开发协作、API、状态/事务、履历来源和迁移说明。

## 下一迭代：闭合交换链路

| 负责人 | 工作 | 验收标准 |
| --- | --- | --- |
| A | UniApp继承工具链告警专项升级 | 跟随兼容的DCloud版本组合验证H5/微信，复核npm audit；外部部署前完成，不使用盲目force修复 |
| A | 注册/资料/密码变更、细粒度权限、账号审计 | 未登录401、越权403；密码变更撤销旧会话；数据库迁移兼容已有开发数据 |
| A + B | 独立“我有/我想要”清单 | 不依附物品也能保存需求；字段校验、owner权限、分页、停用；消费者同步契约 |
| B | 交换创建/确认/取消/超时 | 两个并发方案抢同件物品只有一个成功；无部分占用；重复请求幂等；到期释放仅本交换占用 |
| B | 交接及履历可信度 | 2/3参与者确认才完成；来源、证据、发生/记录时间可追踪；自述不能自动成为管理员核验 |
| C | 分类、审核、举报处理 | 查询、筛选、分页、审核冲突、理由必填；所有新增控件纳入共享材质和交互验收 |
| D | 收藏、需求清单、交换邀请/确认 | 无假成功，接口错误可恢复；H5与微信各自验证；真机图片上传/登录/交接路径可复现 |
| 全员 | 跨端集成和可访问性 | 全新clone复现；键盘焦点、移动长表单、空状态、快速弹层、深色与减少动态效果通过 |

## 后续业务

争议证据上传与管理员裁决、维修/流转事件、通知 outbox、统计口径、匹配候选索引/分页/缓存、风控及校园身份核验。外部 OSS 和微信登录由适配器接入，必须配置和验证后才开放入口。

## 当前明确未实现

完整注册/个人资料编辑、独立需求增删改、收藏持久化、内容审核写操作、交换正式创建与占用/确认/交接、自动超时、举报裁决、履历审核、外部通知、OSS、真实微信身份认证。相关页面只能显示“待开发”；后端预留操作返回明确501，不允许给出虚构业务成功。

C-01 分类维护已提供管理端真实读取、筛选/分页和开发环境表单夹具；由于 A-02 分类写接口、版本字段和引用保护尚未合入，正式新增、编辑及停用/删除仍禁用，不能将 C-01 标记为完成。

## 四人每周协作节奏

每项功能先建立 Issue 和契约草案；A/B确认数据与事务，C/D确认消费字段和交互。每周一个可运行纵向切片通过 PR 合入 main。每位成员至少参与一次跨端联调、一次其他模块评审和一次干净clone验收；不使用人为目录权限割裂协作。
