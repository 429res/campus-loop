# A-01 第三批：注册准入与注册接口

状态：团队已确认采用“默认关闭、仅显式开启的开发自助注册”；后端、契约与自动化已在本功能分支实现，待其他成员审核、CI与合入。该策略只用于本地开发和隔离联调，不代表校园身份已核验；本切片完成不代表整个 A-01 完成。

## 已核对依据

2026-09-08 核对根规则、A-01 任务计划、API/架构/后端契约、开放 Issue 与 PR。仓库没有已确认的注册准入决策；现有文档明确要求先决定校园准入方式，并将真实校园身份认证列为未实现能力。当前没有获授权的学校身份服务、短信或邮件配置。

## 已确认的准入决策

| 方案 | 最小行为 | 代价与边界 |
| --- | --- | --- |
| 开发自助注册（本批采用） | 仅在显式 `CAMPUS_REGISTRATION_MODE=DEVELOPMENT_SELF_SERVICE` 时接收公共字段；默认 `CLOSED` | 无法证明校园身份，只适合当前本地/隔离开发和联调；公开部署前必须更换准入策略 |
| 一次性邀请码 | 除公共字段外提交邀请码；服务端只存不可逆摘要并原子消费 | 不依赖外部服务，但需新增邀请码生成、分发、失效和并发消费规则；本切片不应顺带开放管理员发码页面 |
| 校园身份核验 | 由已授权的校园身份提供方返回可验证凭据后注册 | 最符合校园准入目标，但当前没有提供方、字段、密钥、回调与隐私规则；不能用邮箱后缀或假成功冒充核验 |

应用默认关闭注册；关闭时请求返回403且不写用户。本批采用开发自助注册，以显式本地配置开启完成 D 的联调，并在文档和部署配置中明确“不代表校园身份已核验”。邀请码和校园身份核验保留为后续备选，没有获授权前不接外部服务，也不伪造核验成功。

## 请求与响应

新增 `POST /api/auth/register`。公共请求字段仅为：

```json
{
  "username": "student_name",
  "password": "本机输入的至少十二字符密码",
  "displayName": "校园同学"
}
```

- `username` 去除首尾空白后为3–64位字母、数字或 `_.-`，数据库唯一。
- `password` 为12–64字符且 UTF-8 编码不超过72字节，沿用 BCrypt；不回传、不记录。
- `displayName` 去除首尾空白后为1–64字符。
- `role` 固定由服务端写入 `USER`，`status` 固定为 `ACTIVE`；请求出现 `id/role/status/passwordHash/version` 或其他未声明字段返回400。
- 本批不接受 `inviteCode` 或校园身份凭据。校园身份方案的额外字段必须等提供方确定后另行契约，不能提前猜测。

成功返回 `{id,username,displayName,role}`，不返回 token、status、passwordHash 或准入凭据，也不自动创建会话。D 收到成功后跳转现有登录页，由用户使用既有 `POST /api/auth/login` 登录；这样注册与登录失败可独立恢复。

成功响应示例（示例不含真实凭据）：

```json
{
  "code": 200,
  "msg": "成功",
  "data": {
    "id": 123,
    "username": "student_name",
    "displayName": "校园同学",
    "role": "USER"
  }
}
```

## 错误契约

- 400：JSON、字段、用户名、显示名称或密码不符合约束；无用户记录。
- 403：注册模式为 `CLOSED`；不写用户。
- 409：用户名已存在；并发相同用户名只能一个成功，另一个由唯一约束稳定转换为409。
- 500：意外持久化错误；事务回滚，不留下无密码、错误角色或已消费准入凭据但无用户的半成品。

错误继续使用 HTTP 状态与 `{code,msg,data}` 统一结构。消费端不根据中文文案判断流程。

失败响应分别保持对应 HTTP 状态，例如 `400 {"code":400,"msg":"username: ...","data":null}`、`403 {"code":403,"msg":"当前未开放注册","data":null}`、`409 {"code":409,"msg":"用户名已存在","data":null}`。校验消息的具体文本可能随验证器变化，D 只用状态/code 决定交互。

## 实现与并发

注册服务先检查运行时准入模式，再标准化字段和生成 BCrypt 哈希，在事务中插入唯一用户名的 `ACTIVE USER`。数据库唯一键是并发最终防线；捕获该唯一键冲突时只映射为“用户名已存在”，不能把任意完整性错误都误报为重复账号。

既有首版 Flyway 迁移已经提供 `cl_user.username` 唯一约束、密码哈希、显示名称、角色和状态字段，因此本批不需要也没有新增或改写迁移。

本批没有邀请码或校园服务。未来若切换为邀请码，邀请码校验、条件消费与用户插入必须同事务；若切换为校园核验，只有服务端验证外部凭据后才能写入，且外部调用不能伪造或把凭据写进日志。

## 自动化与隔离 MySQL 验收

- 默认关闭及不符合准入返回403，数据库计数不变。
- 合法注册返回安全公开字段，数据库为 BCrypt 哈希、`USER/ACTIVE`，随后可用现有登录接口登录。
- 非法用户名、显示名称、密码和额外受保护字段返回400，无部分用户。
- 顺序重复用户名与两个并发相同用户名请求均只保留一条用户；失败方409。
- 响应、异常和日志不含原密码、哈希、token 或准入凭据。
- 邀请码与校园核验未采用，因此对应验证不属于本批，不能宣称通过。
- H2 用于快速回归；唯一约束和并发结论必须在一次性 `campus_loop_*test` MySQL 库复验，不连接成员日常库。

## 给 D 的稳定约定

D 可按 `username/password/displayName` 三个字段设计表单；本 PR 合入且目标环境明确开启 `DEVELOPMENT_SELF_SERVICE` 前，提交入口保持关闭。注册成功不视为已登录，不保存明文密码，清空密码输入并跳转现有登录页。400 保留非密码输入供修正，403 展示“当前未开放注册”，409 聚焦用户名冲突；消费端按 HTTP/code 分支，不依赖中文文案，也不能把任何失败显示为成功。
