# B-06 分类建边索引与可重复规模基准

2026-09-08。本次只完成B-06的一个切片：建立基准并采用一项纯内存分类建边索引。用户确认200件目标；未获得端到端延迟SLA或生产机器预算，不外推上线容量。其余性能工作未完成。

## 范围与基线

基于main `d5fb035`，旧IndependentDemandMatcher完整冻结为test目录中的ReferenceIndependentDemandMatcher，仅改类名/说明，不走生产路径。数据模型共用不可变输入；两个实现分别产生全部record字段，以完整有序toString值逐项比较，包含规范化ID、方向、分数、排序、理由、命中需求与版本。超限比较完整错误消息，不把部分结果当完整结果。

原实现对每件提供物扫描全部接收物，再查对应需求分类。新实现将同一接收物/分类的DemandChoices按分类反向索引，提供物只访问需要其分类的接收物。仍按物品ID顺序建边，不修改选择需求或枚举环的代码。索引仅活于一次find调用；不是数据库索引、跨请求缓存或新中间件。仍保留n×n边矩阵与原环枚举，未宣称消除所有二次空间/最坏三次工作量。

## 可重复命令与环境

根目录执行（只需Java17和Node，不读取.env、数据库、凭据）：

```sh
node scripts/benchmarks/matching.mjs > /tmp/campus-matching.csv
node scripts/run.mjs test
```

脚本临时javac编译纯匹配器及测试夹具，运行结束清理类文件。固定种子20260908；20/60/120/200件；六种分布：20分类均匀、全部同类、80%集中第一类、每物品4需求、混合停用需求/下架物品/失效用户/占用、完全无命中。固定查询用户1；每物品一名用户（多物品同用户另由差分测试覆盖）。不同规模重新生成固定种子数据，不是一个递增子集，结果数不要求单调。

实测Java17.0.20.1/OpenJDK、macOS aarch64、可见10核，固定-Xms256m/-Xmx256m和SerialGC（Runtime报告maxHeap 259522560字节）。每个独立JVM中各场景/实现预热100次、采样50次，3个JVM；奇偶fork交换原/新执行次序。最终记录期间未同时执行本任务Maven测试，但不是独占压测机器。

CSV记录每fork的中位数、最近秩p95、候选/需求/结果数、每调用分配字节、堆内存池峰值合计。生成输入及完整输出对照均在计时外；find本身的过滤、索引、建边、环枚举、理由生成、排序都计时。分配字节来自ThreadMXBean（不支持时-1）。峰值是共享JVM内存池观测，受前一场景、对照对象和GC影响，不能当单次活跃内存或由其断言内存节省；内存比较以每调用分配为主。没有测网络、SQL、并发吞吐或生产p95。

## 结论和局限

200件范围分类分散、多需求和无命中场景的耗时/分配下降支持保留本次分类索引；密集场景仍受真实边数和生成1001条前的整次拒绝控制，并不能用于提高上限。小规模索引开销和JIT/GC噪声可能抵消收益，表中大于1的比值即本次实测退化；不把所有场景描述为更快。早期15次预热探索还出现20件偏斜场景约2.25倍退化，增加预热后重测，最终完整数据如表。

只测至200件、最多800条生成需求，没有覆盖20000条有效关联的性能压力、千万级数据、并发HTTP、生产数据偏斜和尾延迟。正确性回归继续覆盖原20000解释引用/1000方案保护；不会以本轮耗时承诺更大规模。

## A/D 契约影响

规则仍为independent-v2：分类硬条件、标签只排序、同流向最高贡献/最小需求ID选择、全部命中ID解释、2/3有向环、旋转去重、反向环区分、稳定排序均不变。不启用requiredTags或最低成色。不添加API分页或游标；返回依然是完整推荐或整次422。200件、20000有效需求关联、1000推荐、20000解释引用上限全部保留。legacy wanted入口及旧匹配器未修改。

A：数据库查询、事务隔离、SQL/索引、候选读取成本均未改动；本基准仅测读取后的纯算法，不能声称数据库成本已经降低。正式创建继续实时读取并使用原事务校验，索引不作为预约依据。生产资源/SLA另行确认，不由256MiB基准推导。D：无字段/分页改动，原422超限提示继续使用，不截断或跨候选页拼环。具体接口沿用api-contract/B-02。
