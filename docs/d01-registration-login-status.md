# D-01 注册入口与注册后登录切片

更新日期：2026-09-08。本切片基于 A-01 注册准入 PR #8 的已确认契约实现；D 的 PR 以该依赖分支为基线，在 A-01 合入前不独立进入 `main`。

## 接入范围

- 登录页提供“创建开发账号”入口，并明确注册默认关闭、只供显式开启的本地或隔离环境使用，不宣称完成校园身份核验。
- 注册页只提交 `username/password/displayName`。用户名、显示名称和密码校验与服务端契约一致；客户端不发送角色、账号状态、邀请码、微信身份或其他资料字段。
- 注册成功不保存令牌也不自动建立会话，清空密码后返回登录页，由既有登录接口重新验证账号状态并创建会话。
- 400 显示服务端校验反馈，403 明确环境未开放，409 明确用户名已存在；非敏感字段保留供修正，密码在收到响应或离页时清空。
- 注册写请求超时、网络中断或网关无有效响应时标记为结果不确定，禁止重复提交并引导先尝试登录确认；不会自动循环创建账号。

## 依赖与未实现项

A-01 采用 `CLOSED` 默认模式，只有服务端显式配置 `DEVELOPMENT_SELF_SERVICE` 才允许开发自助注册；账号由服务端固定写为 `USER/ACTIVE`。PR #8 尚未合入时，本切片保持堆叠依赖关系，不把未审后端提交算作 D 的代码。

当前契约没有注册限流状态或恢复查询接口，因此客户端不虚构专用倒计时、验证码或“查询注册状态”请求；若服务端未来提供 429 或恢复接口，须先更新契约再接入。真实校园准入、邀请审核、短信、微信身份和收费服务均不在本切片范围。
