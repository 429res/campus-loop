# C-04 第二切片：交换争议管理端追溯

更新日期：2026-09-08。本切片交付管理端只读追溯和明确标识的组件夹具；管理员裁决尚无契约或实现，不能报告真实裁决闭环或整个 C-04 完成。

## 已实现领域事实

B-04 已实现参与者 `POST /api/exchanges/{id}/dispute`：仅 READY、已经开始交接的本人参与者可用 `{version,reason}` 登记。成功进入 DISPUTED 并追加事件；原所有权不变、物品继续 RESERVED、占用保留、精确需求继续 ACTIVE，新的交接/取消/自动到期停止。原登记者相同规范化理由可精确重放；其他旧版本、状态或参与者操作 409/404/403。

现有本人详情返回持久 participants 与 flows，不能用物品当前 owner 重建历史。交出/收到声明、说明和数据库时间是当前唯一争议依据；B-04 没有附件。B-05 私有履历证据有独立授权关系，不能直接当作争议证据。

## 管理端交付

- `/disputes` 是生产待开发入口，不请求参与者私有 API；`/fixtures/disputes` 仅开发模式注册。
- 固定虚构夹具覆盖双方/三方队列、筛选分页、加载/错误/空态、长争议理由、参与者交接声明、持久物品流向和交换事件。
- 详情显式展示当前服务端后果，不推断实物状态，不提供代确认、代交接、取消、改 owner、释放占用或裁决按钮。
- C-03 管理交换读取页面和 `/api/admin/exchanges` 当前均不存在，因此本切片抽出 `ExchangeTrace` 作为后续 C-03/C-04 可共用的只读展示组件，没有虚构 C-03 已完成。

## A/B 待确认与实现

A/B 需先在对应 Issue/PR 确定管理员读取字段、交接说明可见范围、管理员利益冲突规则、裁决决定与允许状态、版本/幂等请求、精确重放以及每种决定对状态、所有权、需求、占用和履历的原子后果。实现必须复用 B 的交换锁序和事务服务，追加不可覆盖审计；前端 loading 只能防单窗口重复点击，不能证明两个管理员不会覆盖。

若增加争议附件，应复用私有上传的 opaque uploadId、归属校验和授权二进制读取，但建立独立争议引用；不能返回磁盘路径、公开 `/uploads/**` 或任意外链。管理员队列/详情、事件读取和证据均须服务端 ADMIN 校验，裁决事务还要锁内复核操作人仍为 ACTIVE ADMIN。

在上述契约未落地前，本页没有裁决表单或伪造决定枚举。未来收到 409 时须回读最新交换、事件和影响，再由管理员人工重新判断；保留未提交理由，不自动替换 version/hash 或重放。
