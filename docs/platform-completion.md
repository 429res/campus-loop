# 六个站内模块补齐

本次从已上线的 db30c33 开始，保留既有云端部署及统一品牌。旧“后续业务”页未同步当前实现，不能据此重新实现已有交换/履历/审核/收藏/独立需求。

## 交付范围

1. 账号：头像、简介、校园与联系方式（自填、仅本人及管理侧可读），管理权限配置与审计；保留最后一个可用管理员保护。
2. 交换：沿用已实现双方/三方创建、确认、占用、取消、超时与交接；补齐争议处理后的恢复或取消闭环，不由管理员冒充参与者完成交换。
3. 履历：沿用维修/自述/修正/参与者确认/管理员核验，确保各入口可用、事实来源与权限准确。
4. 治理：管理员争议决定、版本冲突和不可变处理记录；通用举报和审核保持已有语义。
5. 用户体验：补齐站内通知与已读管理；下架物品重新提交审核；收藏与需求复用现有流程。
6. 运营：真实趋势、分类分布、交换/审核/举报/账号统计与审计查询；移除面向用户的开发占位页面。

## 事务与兼容

- 新增 Flyway 迁移，不改写已应用迁移；不导入本机日常数据，不清空线上数据。
- 争议操作复用交换行 → 用户 → 需求 → 物品/占用的加锁顺序。恢复保留交接声明并重新赋予交接期限；取消需明确确认物品已归还原主，保留理由与操作人，原子释放占用并恢复物品。
- 角色及权限只能由受授权管理员修改，所有后台接口由服务端控制；客户端字段不能提升权限。
- 站内通知只返回当前用户的数据，通知失败不能造成业务提交与通知状态分裂。
- 微信登录、短信/邮件及学校身份核验不在本批范围；OSS 是可选存储接入，按账号可用性单独确认，未配置时保留现有上传存储。

## 验收与发布

后端隔离测试与 MySQL 并发/迁移验证，管理端/H5/小程序构建，浏览器主要流程，云端备份后迁移与回归。代码提交 GitHub 分支并建 PR，CI 与另一成员审核后才合并 main；服务器以明确提交版本部署供所有者测试。
