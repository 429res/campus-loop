# 个人主页与交易体验验收（2026-09-09）

本次在同学试用反馈修复基础上完成九项增量，保留已有框架、路由与交换事务服务。公开主页参考二手社区的个人展示、在架物品与完成交换统计结构，继续使用 Campus Loop 品牌与共享设计变量。

| 反馈 | 实现 |
| --- | --- |
| 查看他人的主页和发布物品 | 点击物品、动态、评论、匹配卡片头像进入公开主页；展示头像、昵称、简介、校区与在架物品 |
| 完成交换仍出现在首页；他人看不到头像 | 公开目录仅显示 AVAILABLE / RESERVED，历史详情保留 EXCHANGED；物品返回并渲染 ownerAvatarUrl，其他公开场景复用 MemberLink |
| 资料编辑入口混在“我的” | “我的”改为功能入口；个人资料与密码维护在独立页面 |
| 动态关联物品缺少状态 | 关联卡片显示未交换、已占用、已交换或不可见状态 |
| 不匹配时仍希望自愿交换 | 详情可选择本人的任意可用物品，按分类/标签提示；不一致二次确认，显式 direct-v1，共用原占用与交接事务 |
| 60 分难以理解 | 用户端显示分类与共同偏好标签依据，说明不代表价值或成交概率 |
| 消息不醒目 | 铃铛未读徽标、前台约 5 秒轮询浮层；可关闭、查看、标记已读，切换账号隔离迟到响应 |
| 我的物品不明显 | 我的物品、我的交换作为个人中心首屏大入口，并保留匹配页入口 |
| 订单列表与详情混在一起 | 默认订单卡片列表，标题为交换物品名称，附双方/三方图片；选择后单独显示详情，可返回列表 |

## 接口、迁移与旧数据

新增公开成员读取，ItemView/Post/ExchangeView 只增加字段。无需数据库迁移，Flyway 仍为 V19。新订单记录不可变物品标题/图片快照；旧订单优先原推荐标题，图片回退到仍公开的物品，无快照旧记录回退到公开物品内容。非参与人访问订单仍为 404。公开主页不包含联系方式、账号名、角色、权限或认证信息。

推荐模式仍要求分类匹配。主动交换仅双人，每人一件；不占用或履行无关独立需求，但严格校验真实用户、审核、可用状态、物品版本、唯一占用、幂等摘要，且沿用双方确认、取消、超时、争议和交接状态机。

- 公共成员 API 验证头像、隐私字段和停用用户不可见；公开目录移除完成物品，动态状态与订单快照兼容读取。
- Chrome 使用本机隔离 MySQL 和真实 API：登录、他人头像/主页、资料入口与返回、详情选择不匹配物品、二次确认、正式发出邀请、订单列表/详情切换；再通过两个虚构账号完成真实 API 交接，核对目录移除、主页统计、动态 EXCHANGED、浮层出现与点击更新已读。
- 桌面浅/深色与 390px 浏览器布局检查覆盖个人中心、公开主页、订单和校园动态。标签推荐实际显示共同偏好“阅读”，不再显示 60 分。
- 微信为构建及产物检查，未执行开发者工具或真机交互。浮层是站内前台轮询，不是系统级离线推送。

本机使用独立的 campus_loop_feedback_test 及自动创建销毁的 MySQL 测试库；测试写入全部为虚构数据，线上验证只读。线上版本与部署结果另记录于 aliyun-test-deployment.md。
