# D-02 独立需求清单与本人提供物品关联

更新日期：2026-09-08。本切片消费已合入 `main` 的 B-01 契约，只实现用户端独立需求管理和受保护的本人候选物品关联；收藏、正式交换和 B-02 匹配不在范围内。

## 接入行为

- `GET /api/demands` 按本人、状态和服务端分页读取；新建、编辑、状态切换和逻辑删除分别使用契约规定的 POST/PATCH/PATCH status/DELETE，停用不显示成删除。
- 编辑、停用、恢复与删除始终发送服务器返回的 `version`。409 时不递增本地版本、不自动覆盖，编辑表单保留当前输入并读取服务器版本供用户核对。
- “我有什么”只调用 `GET /api/demands/offerable-items`，不从公开物品列表按 ownerId 过滤。`offeredItemIds` 在用户改变选择时全量替换；未改变关联的编辑请求不重复写关联。
- 需求允许 `offeredItemIds: []`。无候选物品时仍能创建和管理需求，页面明确说明此时暂不能组成交换环。
- 仅展示已确认的分类、可空描述和偏好标签；不提供 `requiredTags`、最低成色等 B-02 字段。历史失效关联按服务端 `offerable=false` 展示并允许移除。
- 旧物品 `wantedCategoryId/wantedTags` 继续服务当前推荐，本页不回填、不合并也不双写；B-02 独立匹配后端已合入 main，但当前推荐页尚未消费该入口。
- 写请求无响应时标记结果不确定并停止重复提交，先重新读取需求与候选。401 进入统一重新登录路径，403/404/409 保留真实错误语义。

## 给 B / A 的契约反馈

B-01 的 `offerable-items` 已满足 D-02 选择本人合法候选的权限边界，并能通过需求详情返回历史失效关联；本切片未发现阻塞字段。A-02 的完整本人物品列表、编辑与下架接口已通过 PR #16 合入 main；本切片尚未接入完整物品管理页面，因此 profile 保持该部分待开发，不把候选接口冒充完整物品管理。候选关联本身不占用物品，也不代表进入现有推荐。
