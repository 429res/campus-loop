# D-03 正式交换与邀请操作

更新：2026-09-08。本功能分支在阶段二修复 `e3d90e6` 上接通 A-03/B-03/A-04/B-04 的现有接口，交付正式发起、我的交换、确认/取消、实物交接、争议登记与错误恢复。没有另写交换状态机或占用接口。

## 从推荐发起

推荐继续只读。用户打开“发起前预览”，核对参与者、物品方向和命中需求，再明确确认正式发起。请求从同一次 `independent-v2` 推荐的物品版本与需求版本组装；缺版本或非法流向时拒绝发起，不填默认版本、不请求他人的私有需求详情。正式创建仍由服务端事务重新校验，发起人也须确认参加。

创建前把完整请求和幂等键作为待核对请求按用户保存在本机，不把它当成交换记录。双击被阻止；相同逻辑请求一直使用原键。请求结果未知时，刷新、切页或重新登录同一账号后仍可核对并重试原请求；即使物品已被占用、推荐返回空，恢复入口仍可见。未知结果不能直接丢弃换新键。已有待核对请求时，不展示新方案却提交旧方案。

发送和回写前核对原发起编号；若其他标签页已替换保留方案，则停止旧请求并恢复当前方案。动作恢复记录同样核对保存修订号，避免迟到结果覆盖另一个页面刚保留的新操作。

服务端明确拒绝时保留原选择并刷新推荐，用户核对后可重新选择。成功响应保存已确认的交换 ID，跳转“我的交换”详情；历史页面缓存不代表当前状态，详情始终从服务器读取。

## 我的交换与操作

- 真实分页与六状态筛选，显示参与者、创建时间与交换进度；详情提供流向、物品标题、各人参加/交出/收到时间与声明、取消或争议原因。
- 流向依据持久参与记录；公开物品读取只补标题，不用当前 owner 重建历史。标题读取失败时明确回退物品编号。
- 页面显示原定截止和本机估算，最终状态与动作资格来自 `allowedActions`；不能因本机倒计时归零自行释放或置 EXPIRED。交接已开始时说明应继续核对实物或登记争议。
- “确认参加”仅表达愿意加入，不代表实物交接。取消/争议原因必填；“我已交出”“我已收到”分别核对本人的提供物品/接收物品，必须明确勾选实物声明，重要动作再次确认。
- 只呈现服务端允许的动作。交接开始后取消消失；COMPLETED/CANCELLED/EXPIRED/DISPUTED 不提供客户端自行推进或管理员代办。

入口保留 `/pages/exchanges/exchanges?id=ID`。会话过期时清除当前展示并引导登录；登录后恢复原详情目标。每个账号的请求保留区独立，旧账号或已隐藏页面的迟到响应不能改写当前页面、弹出提示或发起跳转。

## 冲突、草稿与未知结果

动作在发送前保存原声明、说明和 version。未知结果只能重试完全相同的请求，或重新读取服务器事实核对；读取不会自动当作写成功。409 保留原请求并回读最新详情，用户显式选择“已核对，使用当前版本重新填写”后才可采用新版本，不自动覆盖并重发。

刷新同一详情保留正在填写的草稿、说明和原 version。关闭/隐藏后可恢复草稿；“取消本次填写”只丢弃未发送草稿。明确被拒绝的请求可以在核对后收起；结果未知的请求没有直接放弃按钮。

## 控件与平台

复用 LoopButton、LoopPicker、LoopSheet、showAppModal 与公共材质。状态选择、分页、原因、实物声明、加载/禁用/失败、抽屉与确认弹层纳入 [用户端控件覆盖](../wx-project-self/docs/liquid-glass-controls.md)。H5 使用浏览器能力，微信保留原生按钮/选择/弹窗适配；不会引入 Web 专属密码或存储依赖。

演示双方/三方时，使用不同设备或互相隔离的浏览器配置登录不同虚构账号；同一浏览器普通标签页共享本地会话，不能当成不同参与者。每人先有已审核可交换物品和关联的独立需求，再从推荐发起并分别确认、交出和收到。
