# C-04 第一切片：举报受理与处理队列

更新日期：2026-09-08。管理端界面与组件夹具已实现；通用举报仍是概念能力，不能把本切片报告为真实处理闭环或整个 C-04 完成。

## 实际基础与边界

- Flyway 当前只有 V1–V7，后端没有举报 entity、mapper、service、controller 或测试。`POST /reports` 仍位于 API 契约的未实现草案中，未注册路径可能返回 404。
- 现有 `/uploads/**` 是公开物品图片静态资源，不适合举报证据。页面不把证据当 `imageUrl`，不读取服务端路径，也不加载任意外链。
- `/reports` 是生产管理入口，只展示后端依赖与空队列，不请求不存在的 API；`/fixtures/reports` 仅在 Vite 开发模式注册，使用匿名化固定数据验证组件交互。
- 夹具的“成功”只展示捕获的请求体，不修改本地数组；刷新、重开后仍以固定数据为准。交换争议的下架、占用、所有权或状态机后果不在此切片实现。

## 界面切片

队列包含关键词、状态和目标类型筛选、分页、加载/错误/空态、目标安全摘要、提交人、处理人和时间。详情抽屉以纯文本展示长理由，明确区分目标可访问/已失效、证据可访问/已过期、状态与处理决定，并展示受理人、处理理由和 UTC 时间。

`ReportActionDialog` 覆盖受理与处理两种草案动作、1–1000 字理由、决定单选、版本请求、防重复提交、403/失败保留输入。409 后不会自动重放：管理员需点击重新读取，组件取得当前状态/version 后保留原理由，要求显式重新核对提交。

## A 协作缺口

A 仍需与 C/D 确认目标/状态/决定枚举、受理人是否独占处理、理由限制、重复提交与幂等规则，并实现：

- 会话确定的举报人、受理人、处理人与 ADMIN 权限；非法目标、越权和他人证据拒绝；
- 持久化、乐观并发、成功数据库回读和追加式审计；
- 私密证据上传/归属绑定及授权内容端点，只返回不透明证据 ID、安全元数据和访问状态；
- 队列/详情/审计分页与本人查询，HTTP 400/401/403/404/409/413 的稳定语义。

候选路径与字段在 [API 契约](api-contract.md) 标为 DRAFT，不能在 A 确认前视为可调用接口。

## D 结果展示同步

D 当前只有“规划中”入口。后续本人结果应区分举报 `status` 与 `decision`，显示安全目标摘要、失效状态、处理人显示名、理由和时间；不得显示处理人用户 ID、内部审计快照、他人证据或服务端路径。普通举报决定不承诺自动下架、退款、释放占用或裁决交换。

真实联调需在隔离 MySQL 使用虚构数据覆盖：D 提交 → C 队列 → 受理/处理 → C 与 D 服务端回读、非法目标、非 ADMIN、他人证据、两个管理员旧版本 409、失败回滚和审计保留。本分支没有这些后端证据。
