# C-04 第一切片：举报受理与处理队列

更新日期：2026-09-09。管理端界面与组件夹具已实现；A 已在独立后端切片落地通用举报 API、V15、私有证据授权与审计。C 的生产页面和 D 的提交/本人结果仍未接线，交换争议领域后果也未实现，不能把本切片报告为完整页面闭环或整个 C-04 完成。

## 实际基础与边界

- Flyway V15 新增举报、证据关联和审计表；后端真实路径、字段和错误已固定，见 [通用举报后端说明](c04-generic-reports.md)。
- 现有 `/uploads/**` 仍只是公开物品图片。举报复用 `/api/uploads/evidence` 的本人私有上传，列表不返回上传 UUID、路径或外链，内容仅由本人/ADMIN 的举报证据端点授权。
- `/reports` 管理页面当前仍按原切片显示“待接入”，尚未消费真实 API；`/fixtures/reports` 继续只作为开发组件夹具。C 接线后应移除生产禁用提示，但不得把夹具数据迁入生产路径。
- 夹具的“成功”只展示捕获的请求体，不修改本地数组；刷新、重开后仍以固定数据为准。交换争议的下架、占用、所有权或状态机后果不在此切片实现。

## 界面切片

队列包含关键词、状态和目标类型筛选、分页、加载/错误/空态、目标安全摘要、提交人、处理人和时间。详情抽屉以纯文本展示长理由，明确区分目标可访问/已失效、证据可访问/已过期、状态与处理决定，并展示受理人、处理理由和 UTC 时间。

`ReportActionDialog` 覆盖受理与处理两种草案动作、1–1000 字理由、决定单选、版本请求、防重复提交、403/失败保留输入。409 后不会自动重放：管理员需点击重新读取，组件取得当前状态/version 后保留原理由，要求显式重新核对提交。

## A 已交付契约

A 已确认目标 `ITEM`、状态 `SUBMITTED/IN_REVIEW/RESOLVED`、决定 `UPHELD/DISMISSED`。受理不独占最终决定；理由 1–1000 字；用户提交使用 `(reporter,idempotencyKey)` 幂等且阻止同目标并存待处理记录；管理员写使用版本和完全相同请求重放。已实现：

- 会话确定的举报人、受理人、处理人与 ADMIN 权限；非法目标、越权、受保护字段和他人证据拒绝；
- 持久化、行锁加版本条件更新、成功数据库回读和追加式审计；
- 私密证据归属绑定、大小/摘要快照及本人/ADMIN 内容端点，只返回不透明证据 ID、安全元数据和访问状态；
- 队列/详情/审计分页与本人查询，HTTP 400/401/403/404/409/413 的稳定语义。

最终路径与字段已写入 [API 契约](api-contract.md)。C/D 必须按真实列表与详情投影接线，不从页面夹具反推额外字段。

## D 结果展示同步

D 当前仍只有“规划中”入口。可消费 `POST /api/reports`、本人列表/详情及本人证据内容端点，区分举报 `status` 与 `decision`，显示安全目标摘要、失效状态、处理人显示名、理由和时间；不得显示处理人用户 ID、内部审计、他人证据或服务端路径。普通举报决定不承诺自动下架、退款、释放占用或裁决交换。

后端已在隔离 MySQL 使用虚构数据覆盖：真实提交 → 管理队列 → 受理/处理 → 管理员与本人服务端回读，以及非法目标、非 ADMIN、他人证据、两个管理员竞争、失败回滚和审计保留。C/D 页面到真实 API 的端到端联调仍未执行。
