# D-04 履历、自述、举报与争议用户端接入

更新日期：2026-09-08。本切片只实现用户端消费，不新增后端可信度、举报或争议状态机。

## 已接入能力

- 物品详情进入真实履历分页，区分 `SELF_REPORTED`、`BOTH_CONFIRMED`、`ADMIN_VERIFIED`，展示作者显示名、发生时间、记录时间、修正链、参与者确认进度及有限的公开核验结论。
- 登录用户可按 B-05.1 追加 `REPAIR`/`TRANSFER` 自述与修正，上传最多五张私有证据。上传可取消、失败可重试；从表单移除只取消引用，不声称删除服务端文件。前端不发送作者、owner、来源或核验等级。
- B-05.2 的请求确认、本人独立确认和作者撤回只消费服务端 `confirmation.allowedActions` 与 `snapshotHash`。两方/三方进度直接显示 `confirmedCount/requiredCount`，不按单次点击自行升级。
- “我的交换”读取 `/api/exchanges/mine` 与详情，只在 `allowedActions` 包含 `DISPUTE` 时提交 B-04 `{version,reason}`。成功后使用返回详情并刷新列表；409 或结果不确定时回读，不先移除记录、释放占用或换版本自动重放。

## 未就绪能力

- 通用举报 `POST /api/reports`、本人举报列表/详情仍是 C-04 草案。用户端入口显示目标、原因、证据与提交状态的预期结构，但全部提交控件禁用，不收集输入、不产生编号或本地成功记录。
- 管理员争议读取、附件、裁决、审计及业务后果未实现。当前用户端只能登记并读取 B-04 `DISPUTED`；页面明确不承诺自动下架、退款、所有权回滚或占用释放。
- 管理员核验由 B-05.3 服务端和管理端负责；用户端只读公开投影，不能选择或提交 `ADMIN_VERIFIED`。

## 恢复与隐私边界

- 自述为非幂等追加。超时或响应丢失时保留当前内存表单与上传引用，禁用再次提交，先刷新服务端履历供用户核对。
- 参与者确认使用当前事件返回的快照哈希；409 后重新读取，不把旧哈希套到修正事件。争议结果未知时先查询同一交换状态。
- 私有证据不使用公开 `/uploads/**`，页面不打印令牌、口令、磁盘路径或证据 URL，也不向无权用户显示证据数量。

## 给 A/B/C 的契约反馈

- A/C：请先确定并实现举报目标枚举、私有证据上传/授权、重复提交与未知响应恢复、本人结果安全投影，再开放用户端正式提交。草案中的 `POST /api/reports` 与 `/api/reports/mine` 目前不可调用。
- B/C：B-04 参与者争议已可用，但管理员队列、裁决枚举、幂等键、审计和对 owner/demand/hold/history 的原子后果仍未确定；D 不在前端推导。
- B：当前 B-05 契约足以接入自述、确认和公开核验来源。后续字段变化应继续保持 `recordedEvidenceLevel`、`confirmation`、`verification` 的来源链，不用覆盖原事件。
