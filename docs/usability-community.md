# 发布、匹配与校园动态改进

本轮从新用户完整使用流程验收，延续已部署的站内业务；参考 ProjectStudy-self 管理端的账号目录、角色分类、资料维护、明确操作反馈，以及 Misskey 的动态、回复与表态交互。

## 契约与数据影响

- V17 为发布物品关联一条自动需求，补齐已有物品，发布/修改求换内容与关联需求同事务保存。只有审核通过、未占用的物品参与原双方/三方匹配；原独立需求继续可用，不自动创建交换。自动需求由物品编辑维护，与手动需求区分。
- 匹配入口增加本人参与条件、审核状态与下一步操作；发布后给出明确结果和匹配入口，上传显示预览、进度、成功/失败和替换/移除。
- 管理端区分普通用户和管理员，提供创建、资料编辑、启停、权限分配、密码重置与操作记录。管理员的访问权及密码仅由最高权限管理员管理；保护当前账号与最后一名最高权限管理员。密码不回显、不进入审计。
- V18 新增站内动态、回复、点赞及举报记录。动态可附本人可见物品；纯文本渲染，作者可撤回，COMMUNITY 权限可处理举报与隐藏/恢复。动态与回复按时间分页，用户身份由服务端确定，点赞幂等，回复通知原作者。
- 登录成功替换登录历史；已登录用户返回登录页会恢复目的页面；增加站内返回入口。只在实际认证失败时清理当前会话，网络失败不冒充登出。

## 验收边界

以两位新用户分别发布互补物品为起点，检查审核前提示、审核后自动匹配、交换发起；另验收信息流发布/回复/点赞/举报与管理员处置，以及账号管理、上传反馈和浏览器返回。数据库及并发检查在隔离 MySQL 执行，云端仅用专门虚构记录验证。本轮不启用自动审核、OSS 或其他付费外部服务，不引入 Misskey 服务或联邦网络。

参考：<https://misskey-hub.net/en/docs/for-users/features/timeline/>、<https://misskey-hub.net/en/>。
