# Campus Loop · 四人 Codex 提示词资料包

这套提示词对应[四人任务计划](../team-work-plan.md)，供成员逐个认领后执行。它们描述待开发工作，不是功能完成证明；实际状态以最新源码、已合入 PR 和[路线图](../roadmap.md)为准。共同约束来自根 [AGENTS.md](../../AGENTS.md)，提示词不替代项目规则。

四个文件中的每个 `text` 块都是完整提示词，可单独复制。A-01 等编号沿用任务计划；“第一批”“切片”或 `.1/.2` 表示模块拆分，不是新增主任务。C 的履历核验界面是 B-05 的协作任务；A 的外部适配是可选项，一次只选择已明确需要的一种。

## 成员实际使用步骤

1. 先 clone 完整私有仓库，按根 README 配置自己的环境。仅拿到本资料包不能启动项目；不要共享 `.env`、数据库卷、上传或账号凭据。
2. 确认共同的 AGENTS.md、分工和对应契约已进入自己工作的代码版本。在仓库根目录开启 Codex 任务，用独立 `feature/*` 或 `fix/*` 分支，不在团队文档分支上继续写业务。
3. 从本角色文件复制**一个**完整 `text` 块。若已有相关 Issue、合入 PR、字段决策或明确排除项，在提示词末尾补充；无需重写全部项目背景。
4. 先核对依赖实际可用性。关键规则未定时只澄清影响正确性的部分，并继续独立工作；API 缺失时可完成契约/组件夹具，但业务验收仍需真实接口，不能把待开发改成假成功。
5. 完成本切片的实现、验证和文档后创建 PR，至少另一成员审核且 CI 通过再合并。只更新实际完成的切片，不因一批完成把整个模块改成已完成。
6. 下一个任务重新核对最新主分支与共享规则；项目规则更新后使用新任务/会话检查已读取的来源。详细分支和同步方法见 [CONTRIBUTING](../../CONTRIBUTING.md)。

## 四人并行的依赖顺序

- **第一阶段**：A 的账号/基础 API、B 的需求可并行；C/D 基于已有查询/发布链路完善页面和控件，收到已确认接口后完成真实写入联调。注册准入、审核旧数据处理、新需求与旧字段兼容需要明确决策。
- **第二阶段**：A-03 与 B-03 共用一套创建事务服务；A-04 与 B 共用取消/超时/交接状态规则。C/D 消费同一套接口，不能各自解释状态或另建占用逻辑。
- **第三阶段**：B 提供履历来源/核验领域能力，C 做核验与治理页面，D 做用户履历/举报/微信验证，A 提供通用 API、环境与恢复能力。C-04 所需通用举报 API 由 A 协作、争议状态后果由 B 协作；认领时写明主责，不重复实现。
- **部署前**：按 A-05 复核继承依赖告警、恢复和配置；由 D 实测目标微信环境。OSS、通知及校园身份适配只在明确选定后接入，真实对外操作仍需相应授权。

## 通用的续接与联调提示词

下列三个模板只在对应场景使用，先替换方括号内容；它们不代表新增开发模块。

### 继续尚未完成的同一切片

```text
继续 Campus Loop 的 [角色/任务ID/切片名称]。先读取根 AGENTS.md，核对当前分支、未提交改动、相关已完成代码及最新契约。
上次实际完成：[填写]。本次剩余验收：[填写]。依赖的合入 PR/决策：[填写或明确尚缺]。
复用现有实现，保护未提交工作，不重做已通过且未受影响的验证。按实际证据完成剩余实现与检查，遇到关键依赖仅列出最小阻塞并继续独立工作。
交付真实结果、剩余限制和本切片的 PR；沿用团队审核要求，不自动合并，不把整个模块或其他成员的工作标为完成。
```

### 跨角色接口联调

```text
在 Campus Loop 联调 [任务ID和用户链路]，参与角色为 [A/B/C/D]。读取根 AGENTS.md及本链路契约，先核对双方实际合入的接口与页面版本、分支和已有改动。
完成条件：[填写从用户操作到持久化回读的链路与错误边界]。仅使用本项目独立开发库或临时测试环境及虚构数据；不输出凭据。
先复现契约/页面/服务端的具体差异，再修复本次已认领的范围；跨端破坏性字段变更同步调用方，不另造认证、请求或状态机制。尚未实现的依赖保持明确待开发。
分别报告构建、自动化、浏览器、数据库以及微信工具/真机的实际结果。必要修复走独立 feature/fix 分支和 PR，不自动合并，不把组件夹具当作真实业务验收。
```

### 评审其他成员的 PR

```text
请评审 Campus Loop 的 [PR链接或本地分支]。先读取根 AGENTS.md 和本次相关契约，明确对比基线，只检查本次改动及必要依赖，不修改源码或提交 GitHub 审核意见。
重点找会造成错误行为的问题：契约/权限、状态与事务、数据兼容、公共控件、实际验证缺口。按影响排序，给出准确文件位置、触发条件和建议；不要用无关重构或个人风格偏好阻挡合并。
区分已复现的问题、静态推断与未验证部分；没有实质问题就明确说明。运行必要的本地隔离检查即可，不连接日常库，不对外发送消息。由成员本人确认后提交正式审核，不能将 Codex 自查当作另一名成员的批准。
```

## 导出与维护

源文件维护在本目录；角色提示词随契约变化更新，不复制为个人版 AGENTS.md。导出的总合集和 ZIP 是某次提交的分发快照，使用前应和仓库最新文件核对。

资料包只包含 Markdown 提示词和项目说明，不含源码运行依赖、环境凭据、数据库、真实上传或构建产物。所有操作应在完整仓库中执行；导出快照中的 README/架构是参考材料，不能代替拉取最新代码。
