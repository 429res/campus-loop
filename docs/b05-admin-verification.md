# B-05.3 管理员事件核验（契约草案，未实现）

## 当前依赖与范围

B-05.1 PR #38/#39、B-05.2 PR #41均已合入；本片从main 2aa43c6建立feature/b05-admin-verification。前两片保留原SELF_REPORTED、B-04真实BOTH_CONFIRMED、事件证据引用、修正链及不可变参与者确认快照。ADMIN_VERIFIED尚无写入口。已有AuthInterceptor对/api/admin/**执行ADMIN校验；核验事务还须锁后重新确认管理员仍可用，不能仅依赖请求进入时角色。

本片只核验一个事件的一份内容/证据版本，不变更owner、交换、交接、需求或占用，不裁决举报/争议。原始履历和参与者确认不覆盖；决定追加独立审计来源，原事件和新修正分别显示来源。

## 待确认的关键业务规则

已向用户集中提出以下选择，在得到决定前不实现依赖这些规则的生产核验写入口：

- 只核验链尾具体声明；REPAIR/TRANSFER通过须至少一份可读私有证据，B-04 EXCHANGED可使用完整交接来源链；不强制先取得参与者补充确认。
- ADMIN填写公开范围摘要及私有详细理由，结论限该范围的材料是否支持声明，不表示整个物品历史均真实。
- 不核验本人声明或本人参与交换；一事件一次终局决定，已决定不覆盖。重复同键同内容返回原决定；新修正成为新待核验对象，不继承旧级别。

这些选择影响队列资格、通过按钮、证据快照、利益冲突鉴权及重试契约，尚不能作为已验收API能力。

## 实现调用方案

读取提供管理员分页队列和单事件详情，复用ResultVo/PageResult及现有私有证据读取；公开来源展示只提供安全范围摘要/结论/时间，详细理由、快照、私人参与者信息逐字段授权。修正链非尾只供追溯，不产生新的决定。

写入复用ExchangeTransactionExecutor和数据库UTC，保持可选exchange→用户升序→item→事件锁序，并使用独立锁后查询避免B-05.2已验证的MyBatis一级缓存问题。管理版本/状态用条件更新；审计INSERT与条件更新同事务，失败全回滚。历史快照和原来源保留，读取不创建待办或隐式写行。

A协调下一可用Flyway序号（当前main到V13；计划V14），不修改旧迁移。C消费队列/详情/错误恢复，D消费限定到单事件的核验来源。具体请求字段与状态矩阵在关键规则确定后同步，再接通实现。
