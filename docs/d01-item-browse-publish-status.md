# D-01 物品浏览、发布恢复与本人管理状态

更新日期：2026-09-08。本记录只覆盖 D-01 当前切片，不扩展交换、收藏、审核或需求清单。

## 已完成客户端范围

- 公开列表、搜索和分类切换会取消上一请求并校验请求序号，旧响应不能覆盖新条件；分类失败与列表失败分别重试。
- 空结果与首次无数据分别提示；分页按钮遵守边界，服务端总数变化导致当前页越界时自动回到最后有效页。
- 详情校验物品 ID，支持网络错误重试与下拉刷新；只映射当前已确认的 `AVAILABLE`、`RESERVED`、`EXCHANGED` 状态。
- 发布失败保留按已验证用户隔离的非敏感草稿。恢复不自动发起上传或发布；恢复的上传 URL 在提交时继续由服务端校验本人归属。
- 上传支持取消和失败重试。移除图片只清除表单引用，并明确未删除服务端文件。
- 401 清理本地会话并提示重新登录；登录后返回发布页恢复本账号草稿。

## A-02 依赖与接口问题

当前后端 `ItemController` 只有公开 `GET /api/items`、公开 `GET /api/items/{id}` 和登录 `POST /api/items`。`docs/api-contract.md` 也尚未定义受保护的本人列表、本人编辑或下架接口，因此本切片没有接入“我的物品”、编辑和下架，也没有使用公开列表按 `ownerId` 前端过滤。

请 A-02 在实现前确认并同步到 API 契约：

1. 本人分页列表的路径、查询参数、状态范围与分页响应；必须由会话确定 owner。
2. 编辑的路径、可修改字段、乐观锁/version 输入，以及非 `AVAILABLE` 状态的 409 规则。
3. 下架的路径、幂等语义、允许的源状态、返回体，以及 owner 越权的 403/404 取舍。
4. 状态枚举与可执行动作是否直接随物品返回，尤其是 `PENDING_REVIEW`、驳回、下架、占用状态；客户端不自行推导业务动作。
5. 图片替换或移除时旧上传的清理策略；当前客户端仅改变物品引用，不调用不存在的文件删除接口。

接口就绪后仍需补：本人编辑/下架的隔离数据库回读与刷新、跨用户越权拒绝，以及下架物品不进入推荐的验证。当前未宣称这些验收通过。
